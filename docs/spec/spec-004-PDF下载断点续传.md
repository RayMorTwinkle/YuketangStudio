# spec-004 PDF 导出断点续传（图片缓存）

日期：2026-09-23

## 需求

158 页大册导出若中途刷新/断网/取消，已下载图片全丢，重导需从头下载
（下载阶段占整个导出 90%+ 时间）。要求刷新后能续传。

## 方案

图片 dataURL 持久化到 **IndexedDB**（`yks-pdf-cache` DB / `images` store）：

- **key** = 图片 URL 去掉 `?` 后的 path 部分。
  CDN 链接的 `e=`/`token=` 签名会过期轮换，URL 全等做 key 会导致
  刷新后签名变了缓存全失效；path 才是图片的稳定身份。
- **value** = `{ v: dataUrl, t: timestamp }`
- data:/blob: URL 不缓存（本身已是本地数据）。
- 缓存命中 → 直接解码，进度显示「已下载 X/N 张（缓存命中 Y）」。
- 缓存条目解码失败 → 视为损坏，删除后回退正常下载，不让坏数据挡路。
- `idbSet` 后台写、失败仅 warn——缓存是优化项，不阻断导出。
- 取消导出时已写入的缓存保留 → 下次导出自然续传。
- IDB 不可用（隐私模式/禁用）时全链路降级为无缓存，行为同旧版。

## 覆盖范围

`exportImagesToPdf` 是公共管线——课件面板导出与历史课件归档
（`history-capture`）自动同时获得断点续传。

## 已知限制

- 缓存无主动淘汰（依赖浏览器配额回收）；idbClearAll() 已预留，
  后续可在设置页加「清除导出缓存」按钮。
- 阶段 2（jsPDF 组装）不可序列化，刷新后重跑——但实测 158 页
  仅 ~1.8s，可忽略；真正昂贵的是下载阶段，已缓存覆盖。
