## 三、我认为不应该做，或应该收住的部分

### 1. 不要继续扩大“全自动”

当前默认值是正确的：

- `autoAnswer=false`
- `autoJoinEnabled=false`
- `autoAnswerOnAutoJoin=false`
- 考试只填入，不提交

不要再把它们改成默认开启，也不要做“自动交卷”“后台批量答题”。这些不是技术问题，是产品风险。

### 2. 不要在后台批量处理进行中考试

当前 `batchAI` 对不可回顾考试只处理当前已打开页面，其他跳过。这是正确边界，不要为了“批量完整”去后台抓题。

### 3. 不要把匿名统计默认开启当成增长手段

技术上它确实默认开启；但审查角度，这是隐私/合规风险点。更稳的做法是首次启动明确提示，或至少把“匿名统计”在首启时单独展示，而不是埋在设置里。当前实现符合你的要求，但我不建议继续扩大上传范围。

### 4. 不要用“按题型猜新版入口”

`assignments-panel.js:447` 对 type 4 只要 `oldId` 就显示老版入口，即使数据里有 `newId`：

```js
} else if (a.type === 4 && a.oldId) {
  openBtn = ...打开...
}
```

这不一定违背需求（type 4 的 `newId` 实际是 `courseware_id`，未必是新版入口），但“有新版走新版”目前是**按 type 判断，不是按真实入口字段判断**。更稳的做法是让数据层返回明确的 `entryKind/newUrlAvailable`，不要在 UI 层猜。

### 5. 不要再在 Android WebView 里用原生 `confirm`

设置页还有两处：

```text
src/ui/panels/settings.js:272  强化遥测确认
src/ui/panels/settings.js:589  重置确认
```

项目里已有 `confirmDialog`（自绘，WebView 可用），但设置页这两处还是 `confirm()`。Android WebView 中原生 confirm 可能直接返回 false/不弹，导致“无法开启强化遥测/无法重置”。这是审查发现的真实问题，不是防御性警告。

### 6. 不要把“标记轨”当成滑动条

当前 `presentation.js:309-335` 只创建 marker 按钮。40 页以上时标记会重叠，用户也不能拖动。更好的做法是：

- 保留原生滚动条；
- 右侧只做 minimap 标记（点击跳转）；
- 若要自定义，增加可拖动的 thumb，而不是只有按钮。

### 7. 不要对所有题都无条件截图

`batchAI` 对 type 19/20 每题都 `captureProblemCard`。图片确实需要，但每题都截图会放大延迟和 token。更好的做法：

- 文本/HTML 足够时只发文本；
- 有图片、公式、加密字体或文本为空时才截图；
- 批量队列逐题失败继续，不阻塞整批。

## 四、审查发现的具体问题

### P1：自动进入课堂循环无法真正停止

`src/state/actions.js:393-437`：

- `_autoJoinStarted` 只置 true，从不复位；
- `stopAutoJoinLoop()` 只把 `repo.autoJoinRunning=false`；
- 用户在设置里关闭“自动进入课堂”不会调用 stop；
- 重新开启也无法重新启动（`_autoJoinStarted` 仍为 true）。

结论：自动进入课堂目前只能“首次启动后一直跑到刷新页面”，不能算稳定。需要加配置变更监听和 start/stop 生命周期。

### P1：设置页原生 confirm

见上。建议统一替换为 `confirmDialog`。

### P2：type 4 的新版/老版入口判断不精确

见上。建议数据层明确 `entryKind`，不要用类型硬编码。

### P2：课件轨不是滑动条

见上。

### P2：自动进入课堂缺少测试

没有 mock `getOnLesson/checkinClass` 的自动化测试，也没有真实课堂验证。建议先加单测，再做真机。

## 五、更好的做法（按优先级）

1. **先修 P1**
   - 自动进入课堂：配置关闭立即 `stopAutoJoinLoop`；重新开启能重启；`_autoJoinStarted` 正确复位。
   - 设置页 `confirm` 全部换 `confirmDialog`。

2. **课件导航**
   - 原生滚动条 + 右侧 minimap；marker 只做定位，不替代滚动。
   - 页面多时用 `IntersectionObserver` 更新当前页，不再每次 scroll 全量重建 marker。

3. **作业入口**
   - 数据层返回 `entryKind: 'new'|'old'` 和可用 URL；UI 只渲染这个字段。
   - 不要用 `type===4` 推断“没有新版”。

4. **批量 AI**
   - 改成逐题队列，显示每题状态；
   - 条件截图；
   - 已作答题目默认跳过，避免重复花钱。

5. **设置页**
   - 当前 5 个分区仍是一条 3000+px 长页；更好的做法是 AI/自动/提醒/隐私 4 个 tab 或折叠面板，减少滚动。
   - 保存状态已有，继续保留。

6. **验证顺序**
   - 先 mock 自动进入课堂；
   - 再真机安装 APK；
   - 再真实考试页；
   - 最后真实课堂课件/题目。

## 六、最终判断

- **已完成且可以对外说**：课程切换、刷课成绩、课件单列/题目组件/AI 图源、提醒收起、设置页、关于互通、历史课件统一入口。
- **代码完成但不能说“稳定”**：自动进入课堂、新版/考试工具栏、真实批量 AI、真实图片题。
- **不应该继续加码**：自动交卷、后台批量考试、默认自动进入/自动作答、无依据的新版入口猜测、WebView 原生 confirm。
- **最值得先修的两个点**：自动进入课堂生命周期、设置页 confirm。它们不是体验问题，是会直接导致功能关不掉或点不动。
